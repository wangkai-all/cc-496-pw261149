# churn-watch · 客户流失预警

按**版本化特征**生成风险分层的客户流失预警应用。每个分层都能下钻到可解释的证据链、数据时间与缺失原因；特征修订、客户合并、标签回溯都只重算受影响客户，历史预警与历史评分保持可查；告警去重、关闭、重开；并有专门的验证页对比「迟到标签」与「标签撤销」对判定结果的影响。

零依赖：Python 3 标准库（`http.server` + `sqlite3`）+ 原生 ES Module 前端（无构建步骤）。

## 快速开始

```bash
python3 -m churn.demo      # 重建演示库 data/churn.sqlite 并回放整条时间线
python3 -m churn.server    # http://127.0.0.1:8765
```

`churn.server` 启动时若库为空会自动回放演示数据。可用环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CHURN_DB` | `data/churn.sqlite` | SQLite 文件路径 |
| `HOST` / `PORT` | `127.0.0.1` / `8765` | 监听地址 |

前端页面（顶部标签）：

- **风险总览** —— 风险分层构成随时间变化、各分层客户数、首要证据、数据质量徽标（缺失 / 陈旧 / 迟到）、打开中的告警；按分层、行业、区域、名称筛选。
- **告警中心** —— 打开中 / 已关闭 / 全部；每条告警的时间线（打开、去重命中、等级变化、关闭、重开）、运营反馈、关闭与重开操作。
- **客户档案** —— 证据链图 + 证据表（取值、权重、贡献、数据时间、可用时间、陈旧度、缺失原因）、评分轨迹、修订历史（当前采用 / 截止后到达 / 已被取代）、标签版本、告警与反馈、以及修订 / 合并 / 标签回放的操作面板。
- **版本对比** —— 同一数据截止时间下切换特征集版本，逐客户分数与逐特征贡献差异。
- **验证与回溯** —— 三种标签口径的精确率对比、判定翻转清单、标签台账（延迟天数、回溯、撤销、对告警的影响）、缺失原因分布、迟到修订。
- **运行审计** —— 每次打分运行（范围、重算数、跳过数、跨层变化、特征集、耗时）与任务记录（受影响客户清单）。

顶部的**数据截止**下拉可以切到任意一次历史打分时点，页面会按当时的可见数据重新呈现——迟到的数据与标签不会被回灌到过去，告警状态也由事件日志重建（尚未发生的关闭、合并、撤销不会出现）。历史时点下写操作面板会切换为只读提示。

## 模型与数据语义

### 评分（可解释、可复核）

```
contribution = weight × direction × clamp((value − anchor) / scale, −1, 1) × 50
score        = clamp(50 + Σ contribution, 0, 100)
```

分层阈值：极高 ≥ 75、高 ≥ 55、中 ≥ 35、低 < 35；极高 / 高会开告警。特征：

| 特征 | 权重 | 说明 |
| --- | --- | --- |
| `logins_30d` 近 30 天登录 | 0.30 | 越低风险越高 |
| `support_tickets_30d` 30 天工单 | 0.22 | 越高风险越高 |
| `seat_utilization` 席位使用率 | 0.22 | 越低风险越高 |
| `invoice_overdue_days` 最长逾期 | 0.16 | 越高风险越高 |
| `nps_survey` 最近 NPS | 0.10 | 越低风险越高 |

缺失特征贡献 0 分，但会带**原因码**（未采集 / 上游故障 / 未满成熟窗口 / 客户拒绝 / 业务不适用 / 等待回填）与来源系统，不会被当成 0 值参与打分。超过 45 天的数据标记为陈旧。

### 双时间轴（bitemporal）

每一条特征修订和标签都带两个时间：

- `effective_at` —— 业务时间，数据/结果实际发生的时间；
- `available_at` —— 平台时间，我们在什么时候才能看到它。

一次打分运行只使用 `available_at <= as_of` 的修订，**不会看到未来**。同时满足 `effective_at <= as_of < available_at` 的修订是「迟到数据」：业务上已经存在，但当时还没到，评分只能基于更旧的版本，证据上会标注「迟到 N 天」。`effective_at > as_of` 的修订在业务时间上还不存在，不算迟到。

`backdated`（回溯）是标签上的同类概念：业务时间早于进入系统时间。

同一套时钟也约束**告警的读取**。`warning` 行只保存当前状态，但每次告警事件都记录了它确立的等级 / 关闭原因；历史截止时间从事件日志（`warning_event.at <= as_of`）重建当时的告警状态，因此 10-21 的视图不会显示 10-23 才发生的误报关闭或 11-03 才发生的合并。标签与反馈同样投影：截止时尚未到达的结论不会出现在台账里，撤销在它被录入之前也不会让旧标签失效。

### 增量重算

所有会改变风险的写操作都经过 `engine`，并且只重算受影响的实体：

- **特征修订** `revise_feature` —— 追加一版（旧版标记 `superseded`），只重算该客户（合并后解析到存续实体）；
- **客户合并** `merge_customers` / `undo_merge` —— 只重算合并双方，并把被并入方的打开告警以 `merged` 原因关闭；
- **标签回放** `replay_label` —— 追加标签版本并只重算该客户，同时把结果回填到已有反馈。

每次操作都产生一条 `job_run`（含受影响客户清单）和一次 `scoring_run`（`scope=affected`）。分数行 `customer_score` 不可变，历史运行永远可查。

### 合并

`resolve_entity` 沿 `customer_merge` 链解析，只采用 `available_at <= as_of` 且未被撤销的合并（撤销本身也带时间：撤销前的历史时点仍按合并处理）。存续实体在**所有别名的最新修订并集**上打分，所以合并能真实改变分数；被并入方的历史评分与告警不做改写。合并可撤销。

### 告警生命周期

- 每个客户最多一条**打开中**告警（部分唯一索引 `uq_warning_open`）；重复命中只累加 `occurrences` 并写一条 `deduped` 事件；
- 关闭是终态：`dismissed`（误报）、`resolved`（已处理）、`duplicate`（重复），以及系统的 `recovered`（风险回落）与 `merged`（客户合并）；
- 关闭后仍可查询；再次触发会新建一条告警并通过 `supersedes` 接续上一条，手动重开则沿用同一条告警；
- 用旧截止时间重放运行不会覆盖更新的告警状态（`stale-run guard`）；
- 反馈（有效 / 误报 / 不确定）记录在告警上，之后到达的标签可以把结论回填到反馈；确认流失的标签会推翻「误报关闭」并重开告警（若已有新的打开告警，则在该告警上记录一条推翻事件）。

### 标签与验证

标签是追加式版本记录。**撤销**不删除旧记录：旧版本被标记 `retracted=1`，并追加一条 `unknown` 版本记录撤销本身；关联反馈的结论被标注为已撤回但保留。

验证页用同一批告警做三种标签口径的复核：

| 口径 | 定义 | 用途 |
| --- | --- | --- |
| `on_time` | 告警打开后 30 天内**已知**的标签 | 复盘时当时能看到的结论 |
| `eventual` | 全部标签（剔除撤销），按业务时间判定 | 回测应使用的真相 |
| `include_retracted` | 未剔除撤销标签 | 量化撤销带来的噪声 |

三者的精确率差异即「迟到标签」与「撤销」的信息价值/噪声；「判定翻转」表逐条列出判定发生变化的告警、延迟天数与原因。三种口径都只使用所选截止时点之前已知的标签——把它们切到历史时点，看到的就是当时能得出的结论，而不是用今天的真相回判过去。

## 演示时间线

`python3 -m churn.demo` 用真实引擎按业务时间回放 2026-09 ~ 2026-11 的操作（13 次打分运行、8 个任务）：

1. 基线全量（10-07）与周期全量（10-21）；
2. 北辰数据的告警被运营以「误报」关闭；
3. 旧账套并入临川医药（11-03 生效并可知）→ 存续实体跨层；
4. 北辰数据席位数据的业务时间 10-28、直到 11-04 才到 → 10-29 的评分只能基于旧值（证据标注「迟到」），周中补数后才用上新值；
5. 青禾食品席位回填（只重算一家）；
6. 北辰数据确认流失（业务 10-31 / 入系统 11-06）→ 推翻此前的误报关闭；
7. 星桥教育标签回溯 18 天、白鹭文旅续约标签迟到 21 天；澄海物流标记流失后又撤销（11-08）；
8. 全量复核（11-10）、撤销合并（11-11）、最终全量（11-16）。

- `test_merge.py` —— 合并生效时间、别名反向解析、并集打分、只重算受影响客户、历史不改写、撤销与撤销的时间语义；
- `test_warnings.py` —— 去重、关闭终态、重开链、恢复关闭、合并关闭、旧运行守卫、部分唯一索引、反馈约束、按截止时间重建告警状态；
- `test_labels.py` —— 标签版本、迟到/回溯、撤销语义、误报被推翻、三种口径与判定翻转、撤销在录入前不可见；
- `test_demo.py` —— 演示回放的完整性与跨页一致性；
- `test_api.py` —— 真实 HTTP 服务上的静态文件、路径穿越防护、各读接口、写操作（反馈/关闭/重开、修订、合并/撤销、标签回放/撤销、特征集切换、重置）。

## 目录

```
churn/
  schema.py    DDL（追加式版本、双时间、告警/反馈/任务）
  store.py     SQLite 连接与时间工具

  scoring.py   实体解析、特征可见性、打分与解释

  queries.py   页面所需的读模型（组合、历史投影、版本、验证、审计）
  seed.py      12 家客户的种子数据（数据，不含行为）
  demo.py      按业务时间回放演示时间线
  server.py    JSON API + 静态文件服务
web/
  index.html   应用外壳（截止时间选择、主题、标签导航）

tests/         unittest 用例
```
